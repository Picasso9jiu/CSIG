# DREAM 算法报告

## 摘要

DREAM（Density-Routed Event Attention Memory，密度路由事件注意力记忆）是面向
EV-UAV Challenge 2 的事件级微小目标检测方案。输入是一段带时间戳和极性的事件流，
输出为每个原始事件的二值目标标签。方案针对不同视频事件量差异较大的特点，采用低密度
专家与高密度时序专家的固定路由，并在高密度路径中引入双向时序记忆、时间自注意力、
有界目标流对齐和错相时间分支。网络输出之后，再使用时空组件过滤、弱轨迹恢复、轨迹
质量加分和持续背景组件核验，最后形成符合官方格式的 TXT 提交文件。

最终提交使用的是 M244 归档。M244 只在已经冻结的 M233 主预测包上执行了一个无标签、
可审计的极高密度域 Top-4 恢复规则。官方平台保留结果为 Score=0.9347。

## 1. 任务定义与输入输出

每个视频以 NPZ 文件保存，事件数组字段为 x、y、t、p；其中 x、y 为空间坐标，t 为
时间戳，p 为极性。推理时不读取目标标签、target id 或视频名称。提交 TXT 对每个
输入事件保留原始顺序和前四列，只追加预测标签：

```text
x y t p label
```

其中 label 只能为 0 或 1。提交包包含 31 个测试视频 TXT 文件，且每个文件的行数必须
与对应 NPZ 的事件数完全一致。

官方评分采用：

```text
Score_Fa = exp(-10000 * Fa)
Score = 0.4 * Pd + 0.3 * Score_Fa + 0.2 * IoU + 0.1 * Acc
```

隐藏测试标签不公开，因此本地可以核验提交格式和事件级变换，但不能独立重算官方平台
Score。

### 1.1 数据字段与预处理

仓库同时兼容赛事数据包中用于提交核验的事件数组和用于网络推理的加载格式。快速重建
脚本读取 `ev` 数组中的 `x/y/t/p` 字段；完整数据加载器读取 `ev_loc` 和 `evs_norm`：

| 字段 | 形状/含义 | 推理阶段用途 |
| --- | --- | --- |
| `ev_loc` | `[N, 3]` 的整数 `x, y, t` | 稀疏体素坐标、时空组件和轨迹连接 |
| `evs_norm[:, 0:4]` | 归一化的 `x, y, t, p` 特征 | 网络输入的四个基础通道 |
| `evs_norm[:, 4]` | 事件目标标签 | 仅训练/公开标签评估使用 |
| `evs_norm[:, 5]` | 目标实例编号 | 仅训练阶段构造轨迹监督使用 |

测试推理只保留前四列可观测信息。标签和实例编号不会进入模型输入，也不会参与密度路由、
阈值选择或 M244 审计。加载器在构造样本时保持坐标、特征和事件索引的一一对应；提交
写出前，`verify_submission.py` 再将每一行的 `x/y/t/p` 与公开 NPZ 逐项比对。

主稀疏网络按照 50 个时间单位组织输入。每个非空 `(x, y, t_bin)` 体素聚合该体素内的
事件特征，HAIS_OP 以 mean 模式完成事件到体素的映射，并保留反向的 `p2v_map`，使网络
输出能够准确映射回每个原始事件。聚合只改变计算表示，不改变提交文件中的事件数量和
原始字段。

## 2. 方法总览

DREAM 的最终数据流如下：

```text
原始事件流
  -> 统计整段事件量和极性比例
  -> 固定密度路由（M10 或 M26）
  -> M26 原时间网格 / M111 半 bin 相位网格
  -> 0.75 * 原相位 + 0.25 * 半相位分数融合
  -> P6 密度/极性阈值
  -> P0 时空组件过滤与 P0c 高置信保护
  -> P18 弱轨迹恢复
  -> P32 轨迹质量分数加成
  -> M124 持续背景组件核验
  -> M244 极高密度域 Top-4 无标签恢复
  -> 逐事件 TXT 和 ZIP
```

所有推理阶段的路由、阈值和恢复规则都能由当前视频的公开事件流计算得到；没有使用
隐藏测试标签，也没有使用视频名查表。

## 3. 密度路由

整段视频事件总数是测试时可观测、简单且跨视频稳定的信号。DREAM 使用以下专家路由：

| 条件 | 专家 | 作用 |
| --- | --- | --- |
| 事件数 <= 30,000 | M10 | 处理稀疏输入，减少高密度时序聚合对弱事件的过度平滑 |
| 事件数 > 30,000 | M26 | 使用跨时间上下文和运动约束，处理高密度背景 |

M10 checkpoint 为 `m10_dense_views2_epoch_002_seed42.pt`。M26 checkpoint 为
`m26_targetflow_m20e3_epoch_003_seed53.pt`。完整推理脚本会先按事件数分组，再为
每组调用同一套后处理接口。

## 4. 高密度 M26 主干

M26 由 EV-SpSegNet 稀疏空间表征和全视频时序记忆组成。事件按 50 个时间单位划分
时间 bin，每个样本使用长度为 16 的连续上下文。时序记忆在 bottleneck 特征上运行
双向 ConvGRU：正向状态积累过去证据，反向状态提供未来证据，融合后再送回解码器。

主干的三个关键设计如下：

1. **双向记忆**：降低目标在序列开头、结尾或遮挡片段中的漏检。
2. **时间自注意力**：在长上下文中对更相关的时间 bin 加权，避免简单平均所有历史。
3. **有界目标流对齐**：根据相邻时间 bin 的目标质心监督学习位移，对记忆状态做受
   限平流；最大流量和 Huber 目标流损失限制异常位移传播。

M26 的训练从 M4/DACC/M5 权重开始，依次经过 M13、M15、M20 和 M26 的版本化训练链。
完整配置和每一阶段的 checkpoint 均保存在 `scripts/retrain_m26_chain.sh` 与
`checkpoints/` 中。

### 4.1 稀疏空间主干

EV-SpSegNet 使用稀疏 3D 卷积处理 `x-y-time` 体素，而不是把整段视频展开为稠密的
三维张量。这样既保留事件在空间和时间上的局部结构，也避免绝大多数空体素带来的显存
开销。编码器包含三次带步长的空间/时间下采样，每一级使用 GDBlock 和稀疏子流形卷积
提取局部模式；在中间层加入 patch attention，对活跃体素之间的上下文进行交互。

解码器采用 U-Net 式跳跃连接，将低分辨率的长程上下文逐级恢复到事件分辨率。最后的
`semantic_linear` 对每个活跃体素输出 sigmoid 概率，再通过 `p2v_map` 广播到该体素内的
原始事件。因而一个事件不会因为所在体素为空或被密集帧填充而凭空产生，输出长度始终
由输入事件数决定。

M26 在这个空间主干上增加时序残差，而不是替换已有的局部特征。记忆投影层采用零初始化，
把已验证的基础模型作为起点；新时序分支尚未学到有效残差时，前向结果与基础 checkpoint
保持一致，这也便于逐阶段审计每次改动的实际影响。

## 5. M111 相位互补分支

固定的 50-unit 时间 bin 可能把一个快速目标切在 bin 边界两侧。M111 是在错开 25 个
时间单位的相位网格上训练的一轮专家。发布的 M111 模型由 seed 72、73、76 的三个
一轮 checkpoint 在参数空间进行 float64 平均得到：

```text
m111_phase_specialist_seed72_73_76_average.pt
```

对于事件数超过 30,000 的视频，M26 原相位分数与 M111 半相位分数按以下比例融合：

```text
S = 0.75 * S_original + 0.25 * S_phase25
```

原相位分支保留主模型的稳定性，半相位分支补充因时间分箱边界造成的弱响应。低密度
视频不启用该相位专家，仍使用 M10 路径。

### 5.1 时序记忆的计算过程

对每个视频，事件帧先按固定时间步组成连续序列，再在 bottleneck 特征上计算记忆残差。
正向 ConvGRU 从序列起点向后传播，反向 ConvGRU 从终点向前传播；两个状态拼接后经
零初始化的 `1x1` 投影压回原通道数，并加到对应时间步的 bottleneck。这样，视频开头和
结尾的目标也能获得另一方向的上下文支持。

启用时间注意力时，序列特征在时间维度做多头自注意力，注意力输出作为额外残差加入记忆
结果；可选的相对距离偏置只表达时间距离，不引入视频名称等先验。启用目标流对齐时，
相邻 bottleneck 由一个有界 flow head 估计位移，位移经过 `tanh` 限幅，并用目标质心
构造的 Huber 目标流监督。训练和推理均保留最大位移约束，避免错误运动把背景证据传播到
远处区域。

M111 并不把未训练的相位平移直接混入主分数，而是使用同样的网络结构在平移 25 个时间
单位的网格上单独训练。三个 seed 的 checkpoint 先以 float64 对同名张量求平均，再恢复
到模型原始 dtype；该过程由 `scripts/build_m111_average.py` 和参考权重校验脚本固定。

## 6. 事件级后处理

### 6.1 P6 密度/极性阈值

P6 不使用单一全局阈值，而是根据当前视频整段事件统计选择阈值：

| 域 | 可观测条件 | 阈值 |
| --- | --- | ---: |
| 低密度 | 事件数 <= 30,000 | 0.718 |
| 中密度 | 30,000 < 事件数 <= 200,000 | 0.728 |
| 高密度、极性不平衡 | 事件数 > 200,000 且少数极性比例 < 0.20 | 0.722 |
| 高密度、其他 | 其余视频 | 0.724 |

### 6.2 P0/P0c 时空组件

将超过 P6 阈值的事件按空间和时间连接为候选组件。最终 M244 使用空间半径 2、
时间 bin 宽度 50、时间邻域 1、最少 3 个事件和最少 5 个时间 bin 的 P0 规则。
P0c 对被过滤组件中的极高置信事件进行保护，保留分数至少为 0.95 的证据。

### 6.3 P18 弱轨迹恢复

P18 从 P0 保留的种子出发，寻找分数至少为 0.53、空间可链接且时间连续的候选轨迹。
使用空间半径 5、最大链接距离 8、最多跨 1 个时间 bin、最少 4 个时间 bin；每条满足
条件的轨迹只恢复最可信的一个弱事件，避免直接降低全局阈值导致虚警增加。

### 6.4 P32 轨迹质量加分

P32 对已有候选分数做结构化加权，而不凭空产生事件。候选分数至少为 0.60，并且轨迹
至少覆盖 4 个时间 bin、包含至少 3 个种子组件、最大运动残差不超过 2。满足条件时加
0.010 分，最终分数上限为 0.97。

### 6.5 M124 背景组件核验

M124 是冻结的持续背景组件 verifier。它针对高密度视频中可能长期存在的热噪声背景
组件进行额外判断。基础 artifact 不变，只根据整段视频的事件量和极性比例生成阈值副本：

| 域 | 路由条件 | M124 阈值 |
| --- | --- | ---: |
| low_middle | 事件数 <= 200,000 | 0.94 |
| h1 | 事件数 > 200,000 且少数极性比例 < 0.20 | 0.62 |
| h2_other | 其他高密度视频 | 0.65 |
| h2_extreme | h2_other 且事件数 >= 500,000 | 0.63 |

域划分由 `scripts/split_m244_domains.py` 完成，规则中没有视频名称或标签条件。

### 6.6 后处理执行顺序与评分取舍

后处理严格按“阈值 -> 组件 -> 轨迹 -> 背景核验”的顺序执行。组件过滤先处理孤立的
高分噪声，P0c 再保护极高置信证据；P18 和 P32 只在已有种子支持、且时间上可连接时
恢复或重加权事件。M124 最后检查持续背景组件，避免前面的恢复把长期热噪声重新推过
阈值。每一步都只修改事件的分数或二值标签，不修改 `x/y/t/p`。

这个顺序对应官方指标的不同侧重点：P0/M124 主要控制 Fa，P18/P32 和相位融合主要
保护 Pd 与 IoU，P6 则在不同事件密度下调整取舍。由于 `Score_Fa=exp(-10000*Fa)`，
Fa 很小时继续追求极小的下降收益有限；DREAM 因此把额外恢复限制在有时空证据的少量
事件上，避免以明显的虚警代价换取召回。

## 7. M244 最终无标签恢复

M244 是 M233 的保守扩展。M243 审计先在极高密度视频的冻结原始分数中寻找“该 50-unit
时间 bin 原本没有 M233 正事件”的候选 bin，再按每个视频的最大原始分数排序。M244
对每个极高密度视频选取 Top-4 候选 bin，并将每个 bin 中分数最高的一个负事件恢复为 1。

在发布测试输入上，该规则只修改：

- `test_022` 的 4 个事件；
- `test_023` 的 4 个事件；
- 其余 29 个视频与 M233 完全一致。

总共只恢复 8 个事件。选中的事件索引、原始分数和规则证据保存在
`artifacts/m243_test_actual.json` 及两个 `.npy` 原始分数文件中；
`scripts/rebuild_m244.py` 会逐行检查恢复操作，避免人工编辑提交包。

M244 的“无标签”含义是：规则输入只有公开测试事件和冻结的 M243 原始分数。审计阶段
只判断时间 bin 是否为空、候选事件的原始分数排序以及是否满足极高密度域条件；没有读取
测试标签，也没有根据平台返回的 Score、Pd 或 Fa 反向修改规则。由于恢复数量固定且有
明确的事件索引，审查人员可以复核每个变化来自哪一个公开输入和哪一条规则。

## 8. 训练方案

主模型训练链为：

```text
M4 + DACC + M5 -> M13（epoch 003） -> M15（epoch 008）
-> M20（epoch 003） -> M26（epoch 003）
```

训练数据只使用官方 `train/`，不混入验证集标签或隐藏测试标签。M111 相位专家为三个
独立的一轮训练结果，平均过程使用 float64；推理阶段冻结 M10、M26、M111 和 M124。

各阶段的职责和发布权重如下：

| 阶段 | 初始化/训练内容 | 发布选择 |
| --- | --- | --- |
| M4 | DACC/M5 基础事件分割模型 | `m4_dacc_m5_best_loss_seed42.pt` |
| M13 | 在密集视频视图上微调 | epoch 003 |
| M15 | 低学习率继续微调 | epoch 008 |
| M20 | 注意力和密集视图配置 | epoch 003 |
| M26 | 双向记忆、时间注意力和目标流对齐 | epoch 003 |
| M111 | 25-unit 错相专家，seed 72/73/76 各训练一轮 | float64 参数平均 |

训练阶段使用目标标签只计算损失和目标流/轨迹监督；部署阶段把网络和所有规则冻结。验证
集可以用于开发期比较模型，但最终发布链不把验证标签塞入训练集，也不通过测试集标签
选择模型或阈值。这一边界保证了报告中的固定路由在最终隐藏测试上仍然是可执行的推理
策略，而不是逐视频查表。

一键完整训练和测试入口为 `scripts/run_train_and_test.sh`。由于完整训练包含多个阶段，
实际运行时间取决于 GPU 和数据存储速度；若只需审查最终提交，应优先使用 README 中的
快速 M244 重建命令或直接验证 `artifacts/m244_reference_submission.zip`。

完整训练入口会为每一阶段创建独立输出目录，并在阶段结束时检查预期 checkpoint 是否
存在，再将其传给下一阶段。这样可以从中断阶段继续检查，而不需要把不同版本的权重
覆盖到同一路径。完整推理入口则将低密度和高密度视频分组运行，最后合并 TXT；输出合并
前后都会检查文件数量、事件行数和视频名集合。

## 9. 最终结果与复现边界

官方平台保留的隐藏测试结果：

| Score | Pd | Fa | IoU | Acc |
| ---: | ---: | ---: | ---: | ---: |
| **0.9347** | 0.9318 | 5.56e-06 | 0.9065 | 0.9694 |

仓库可复现：

- 完整源码、训练配置、推理配置和自定义 HAIS_OP 源码；
- M244 所用模型及 M124 verifier artifact；
- 官方提交 ZIP 的快速重建和逐事件格式核验；
- 从头训练 M26 主链的命令和中间 checkpoint。

仓库不能本地复现：

- 官方隐藏测试标签；
- 没有标签时无法独立计算的官方平台 Score。

### 9.1 复现层级和数值边界

| 复现层级 | 所需条件 | 可核验内容 |
| --- | --- | --- |
| 快速 M244 重建 | Python 3.9、NumPy、公开测试 NPZ | 31 个 TXT、事件顺序、标签范围、总正样本数和官方 ZIP SHA-256 |
| 发布 checkpoint 推理 | NVIDIA GPU、CUDA 11.1、spconv、HAIS_OP 和 Git LFS 权重 | 从 M10/M26/M111/M124 重新生成完整预测链和格式正确的提交包 |
| 从头训练 | 上述 GPU 环境、训练集和验证集、较长运行时间 | M13/M15/M20/M26 阶段 checkpoint 及其后续推理结果 |

快速路径不运行神经网络，因此可在没有 GPU 的审查环境中验证官方提交包的完整性。完整
checkpoint 推理会受到 CUDA、spconv 算子实现和 GPU 浮点舍入影响，事件级决策应保持一致，
但 ZIP 的压缩字节或极少数临界分数可能与官方归档不同；报告中的官方 Score 仍以平台
记录为准。模型文件通过 Git LFS 管理，审查前必须执行 `git lfs pull` 并按
`docs/CHECKSUMS.sha256` 校验，而不能使用几十字节的 LFS pointer 文件。

## 10.1 运行时的完整性检查

为了让复现结果可审计，运行链包含三类检查：

1. **输入检查**：确认测试目录包含 31 个 `test_*.npz`，事件字段长度一致，坐标和极性
   在允许范围内。
2. **模型检查**：加载 checkpoint 时核对配置中的输入通道、时间 bin 和序列长度；审查前
   再依据 `checkpoints/MODEL_MANIFEST.json` 与 `docs/CHECKSUMS.sha256` 核对权重 SHA-256，
   M111 平均权重另行执行参考张量核验。
3. **输出检查**：逐个 TXT 检查五列格式、行数、`x/y/t/p` 原样保留以及 label 只能是
   0/1；生成 ZIP 后再检查成员列表和审计 manifest。

这些检查不会使用标签，也不会改变预测结果。它们的作用是尽早发现数据路径、LFS 权重、
时间单位或文件顺序错误，避免把环境问题误判为算法差异。

## 11. 结论

DREAM 的核心贡献是把事件密度这一测试时可观测信号用于专家路由，把错相时间建模与
双向时序记忆结合，并用有明确几何约束的后处理处理稀疏小目标和持续背景。最终 M244
规则只对少量可审计事件做无标签恢复，保留了 M233 主链的可追溯性和复现稳定性。

从工程角度看，DREAM 将“模型权重”和“决策规则”分开版本化：权重负责从稀疏事件中产生
稳定的连续分数，规则负责在事件密度、时空连通性和持续背景之间做可解释的二值决策。最终
发布的代码、checkpoint、审计 artifact、快速重建脚本和运行说明共同构成完整复现材料，
而 `note.md` 则保留了被否决的探索方向和原因，便于后续审查或复用时区分最终链路与历史
实验。
